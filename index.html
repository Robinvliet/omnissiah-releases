What is in it

A workspace that does more than answer

Omnissiah is not a chat window with a memory bolted on. It is a workplace where the model reads files, runs commands, searches your own documents and keeps working on a schedule while you do something else. With safety nets you set yourself.

Agent mode with safety nets

Link a folder and the assistant reads files, writes changes, runs commands in the terminal and executes scripts. You choose per conversation how strict approval is, from approving everything by hand to letting a helper model review every action for you. Under every write there is a checkpoint, and under every command a snapshot of the folder.

Sources and projects

Give every conversation its own documents, or share them within a project. Search combines keywords with meaning, and every answer points back, clickably, to the line in the original.

Tasks that keep running without you

Put an instruction on a schedule, once, on an interval or with cron, and the agent runs it even if the app was closed. Missed runs are caught up, and a task that keeps failing pauses itself instead of quietly muddling on.

Memory and skills

What you tell it once stays, across conversations. Skills are reusable instructions that the assistant writes, proposes and updates itself.

Deep research

Multi-step research within a token budget you set, ending in a report in which every claim points to its source.

Tools and MCP servers

Web search and fetching web pages are built in. Connect your own MCP servers and turn them on or off per conversation.

Privacy

There is no server looking over your shoulder

Omnissiah runs on your own machine and binds to localhost. There is no account, no subscription and no telemetry: nothing comes to us, because there is no "us". What does go out goes straight to the service you are using at that moment. Talk to a cloud model and that conversation goes to that one provider, with your own key. Pick a local model and the conversation stays on your computer.

Storage
Everything in one SQLite file, plus readable folders for skills and memory.
Backup
Copying that one file. That is all there is to it.
Keys
Stay server-side on your own machine and never reach the browser.
Outbound traffic
Only what you switch on yourself: the model you picked, tools such as web search or an MCP server, and the check for new versions.
Questions

Before you install

What does it cost?

The app is free and there is no account. If you use a cloud model you pay that provider directly for what you use, with your own key. If you run a local model it costs nothing.

Cloud and local side by side

Do I need an API key?

For Claude or Gemini yes, you paste it into Settings once. For local models no: install Ollama or LM Studio, and Omnissiah finds them itself.

Adding a model and your first conversation

macOS says the app is damaged

That is to be expected, and it is not really damaged: the app is deliberately not signed, so Gatekeeper blocks it the first time. You clear that once per version, with a button or with a command.

How to clear it

Windows warns about the installer

SmartScreen shows "Windows protected your PC" because the installer is not signed. You can get past it, and this too is once per version.

How to get past it

Does it work on an Intel Mac?

No. The macOS download is built for Apple Silicon, so for a Mac with an M-chip. On an Intel Mac you run Omnissiah as the web version through Docker or Node, which works on the same data.

Setting up the web version

How do I get updates?

The app checks at startup whether there is a new version and reports it at the bottom of the sidebar. Nothing is ever downloaded or installed without your confirmation.

What happens per operating system

Can I use it on my phone?

Yes, but not as a separate app. You run the web version on your computer and reach it through Tailscale, a private network between your own devices. The data stays on your computer.

Setting up Tailscale and installing it as an app

Where is my data, and how do I make a backup?

In one folder on your own disk: a SQLite file with your conversations and settings, plus readable folders for your skills and your memory. A backup is copying that folder.
