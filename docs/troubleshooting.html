Troubleshooting

The app does not start

The error message shows the bundle and data folder. Reinstalling the latest version from the download page is usually the quickest fix; your data stays, because it lives in the app data folder and not in the app itself.

macOS says the app is damaged

That comes with the territory and it is not damaged: the app is deliberately not signed, so macOS blocks it the first time. Clear it once per version through System Settings → Privacy & Security → Open Anyway, or in Terminal with xattr -cr /Applications/Omnissiah.app. See Installation.

Windows warns about the installer

SmartScreen shows "Windows protected your PC" → More info → Run anyway. Once per version, and for the same reason: the installer is not signed.

There is no model at all in the picker

Then there is no key and no local server yet. Go to Settings → Models; First steps walks through it.

The provider returns an error

Omnissiah shows the message with the provider's name in it. A few come up often:

  • 429 from Gemini: the free tier has tight limits on the pro models. Wait a moment, or pick a flash model.
  • 503 from Gemini: flash is temporarily overloaded.
  • 529 from Anthropic: overloaded.

The practical answer is the same every time: switch model or provider and try again. The conversation simply stays, and another model can carry on where the previous one left off.

A local model keeps searching and never answers

Smaller models can end up in a loop with tools and finish their turn without a final answer. The step limit cuts that off, and Omnissiah nudges the model once to finish. Pick a bigger model, from roughly 8B, or give the conversation less to work with: unlink the folder, or switch an MCP server off under Settings → Tools. See Models.

"The prompt does not fit in the context window"

This is almost always a conversation with tools on an Ollama with the default context window of 4096 tokens. The tool descriptions count towards the prompt, and with a linked folder on top it no longer fits. The message quotes your server's own text, including how many tokens were asked for.

Two ways out. Raise your server's window (in the Ollama app under Context length, or start it with OLLAMA_CONTEXT_LENGTH=16384; in LM Studio under Context Length in the load settings of the model) and restart it. Or make the prompt smaller: unlink the folder or the sources, or start a new conversation. See Models.

"The requested answer length is above what this model may produce"

This is a different thing from the context window, and the message says so itself: shortening the conversation or unlinking sources will not help here. The model has a ceiling on how much it may write in one answer, and something asked for more than that.

Pick a model with a higher answer limit, or, if this is your own endpoint, set a lower one for it yourself under Settings → Models. See Models.

The answer stops halfway

If it says "Answer truncated: this model's output limit was reached", the model wanted to write more than there was room for. With a local model that room depends on your server's context window, so a bigger window also gives longer answers. You can also simply ask it to continue.

Starting fresh

Close the app and delete the data folder. That wipes all your conversations and settings. See Data and backup.

Web version: port 3000 is already taken

Set APP_PORT=3001, or another free port, in .env and start again with docker compose up -d.

Web version: what is the app actually doing

docker compose logs -f

Web version: password lost

Delete the authPasswordHash row from the settings table in data/omnissiah.db with a SQLite tool. The login screen then shows "Set a password to get started" again, and your conversations stay.

Web version: something is off after an update

docker compose build --no-cache

That forces a clean rebuild.

Web version: native module error (better-sqlite3)

Build with docker compose up -d --build. The module is then compiled for Linux inside the container, instead of being copied from your host.
