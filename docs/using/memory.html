Working with Omnissiah

Memory

A conversation knows nothing of another conversation. Memory is the exception: a small list of things about you that goes along in every conversation, so you do not have to explain who you are and how you work every time.

You manage it under Settings → Memory: "What the assistant remembers about you. Also readable as data/memory.md; you edit it here."

Two lists

  • User profile - "Who you are: role, preferences, style, how you want to be addressed."
  • Facts - "Loose lasting facts from earlier conversations."

They stand apart, each with its own switch and its own room. An item moves to the other list with To Facts or To Profile.

How it fills up

Mostly by itself. If the assistant learns something lasting about you during a conversation, or a clear preference, it writes it down. It is supposed to be restrained about that: no temporary conversation details and no task progress. If something is out of date it updates the existing item instead of putting a second version next to it.

You can do it yourself too: at the bottom of each list is an input field with Add. Click an existing item to edit it (Enter saves, Escape cancels), or use Delete.

Ask in a conversation what the assistant knows about you and it can call up its whole memory and read it back to you.

Suggestions from conversations

Besides what the assistant stores directly during a conversation, a helper model looks back after every turn to see whether something lasting about you came up. If it finds something, a suggestion appears at the top of the Memory tab: the fact, the reason, and a quote from your own message that it rests on - so approving is not a matter of blind trust. Nothing is stored until you click Approve; Reject drops it, and the assistant will not suggest that same text again for two weeks.

If a list is already full, the suggestion comes with a proposal attached: which existing item it would replace. That item is shown struck through with the suggestion.

This is the same post-turn review that also looks at your skills, with at most one memory suggestion at a time and a ceiling that skill and memory suggestions share: Suggestions per conversation under Settings → General → Helper tasks, 3 by default. If you would rather have no memory suggestions at all, that is what Self-learning memory in the same place is for.

With a scheduled task none of this happens: there is nobody to put anything to.

The room per list

Under each list it says "In use: 1,850/2,200 characters". By default that is 1,375 characters for your profile and 2,200 for the facts; the Limit field next to it changes that.

Characters, not tokens, and that is deliberate: it makes the limit mean the same thing on every model. If a list is full the assistant cannot add anything and is told to clear up first. The counter then turns warning-coloured.

It is a small budget, and that is how it should be. Memory goes along in every turn in every conversation; it is a short summary of who you are, not an archive. For documents and longer notes you have Sources.

On and off

Each list has a switch, with underneath it what switching off does: "Off = not in the assistant's context." A list that is off is also invisible when the assistant calls up its memory, and nothing can be stored in it.

This is the only place where memory goes on or off. Unlike tools and skills there is no switch per conversation.

What the model sees exactly

If there is anything in it, the assistant gets one block in its instructions: first your profile, then the remembered facts. If you filled in a name under What should Omnissiah call you?, that is in there too, with the instruction to address you that way.

Nothing else. Your conversations are not searched to fill the block; what is in it is exactly what you see in Settings.

Where it does not count

In a project with Answer only from the sources the assistant cannot call up its memory, and the block that is in the prompt does not count as a source there: it carries no source number, so you cannot base a claim on it. The contract is about where an answer comes from. See Projects.

Clearing

Per item with Delete; clearing everything is deleting every item. There is no undo, but there is your backup.

Memory itself lives in the database in your data folder, with data/memory.md as a readable copy next to it: edit that copy and nothing changes, because the database is the source. To start completely fresh with everything, you delete the whole data folder; see Data and backup.

And privacy

Memory sits on your own machine and goes nowhere except, as part of the prompt, to the model provider you linked yourself. Switch the lists off and even that stops. See Privacy and security.
