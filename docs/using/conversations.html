Working with Omnissiah

Conversations

A conversation is the unit you work in. The model, its settings and the sources all apply per conversation, so you can have two side by side that behave completely differently. Skills are the exception: you attach them per message, not per conversation.

What a conversation can do

There is no mode to pick. Every conversation is one and the same lane, and what the assistant can do in it follows from things you can see and set:

  • A linked folder, and whether it is read-only or may be written in. That is what decides whether anything on your disk can change. See Working in a folder.
  • The approval level, next to the + on the input bar, for everything that reaches outside the app.
  • A project set to Answer only from the sources, which closes off every route to material outside your sources. See Projects.
  • What your model can do. A model without tool support gets a plain lane and says so: "does not support tools; the assistant can only chat. Tools come back when you pick a model that supports them." Eight steps per turn at most, and nothing is stored - pick a capable model again and everything is back.

How far a turn may go follows the same line: without tools it stops at the eight above, with tools it becomes twenty steps. What the assistant does with them is on Working in a folder.

How thoroughly the model thinks is a separate matter, set with Effort in the model picker. That is on Models.

Deep research, per message

Deep research is not a mode you sit in but something you start for one message. Open the + on the input bar and pick Deep research, or type /research. A chip appears above the input bar and the next message runs as a research run: "several rounds of web research, ending with a saved report." Twenty-four steps, and the web tools are on for that run whatever else is configured.

The assistant runs it as an orchestrator. If your question is broad or ambiguous it asks you one question first, about scope, depth or audience; a sharp question is picked up straight away. It then scales the work to the question: something simple and factual is handled in one go, while a comparison or a composite question is split into a few sub-questions that each get their own sub-agent, with its own context and its own searches. You can follow those in the action timeline. The assistant reads what they found, checks it, and writes the report itself: an answer to your original question first, then one section per sub-question.

How much of this you get depends on the model. The orchestration is an instruction, not a rail, so a small local model may ignore it and simply answer in one go.

The chip disappears once that message is sent, so the run is exactly as long as the research. If the action is greyed out the reason is there: your model knows no tools, there is no Tavily key, or the project is source-bound.

While the run is going the line under the answer says which phase it is in and how many sources have come by so far, next to the elapsed time. The source count jumps rather than creeps: a sub-agent only reports back when it finishes, so everything it found arrives at once.

At the end a report is saved and appears as a card in the conversation. If the assistant forgets, Omnissiah saves the last answer itself and the card says so: "Saved automatically, the model did not save the report itself." Both kinds also turn up under Reports in the sidebar.

A saved report carries one more line, on the card and in the viewer: "All 12 sources appeared in this run", or "3 of 12 sources could not be traced to this run". Omnissiah collects every url the run actually touched - what the searches returned, what was fetched, and what the sub-agents retrieved - and checks the report's own source list against it. It is a mechanical check and nothing more: it says a source came by, not that it says what the report claims it says, and it never blocks anything. Reports from before this check, and automatically saved ones (which have no source list), simply show no line.

Reports in the sidebar is where all of them live: title, age, how many sources, that same source line, and the conversation it came from as a link you can follow. A report you no longer want can be deleted there; it asks first, and the conversation it came from stays.

From that list - and from the card in a conversation, and from the report itself - you can pick Discuss in a new conversation. A fresh conversation opens with the report attached as a source, so you can ask questions about it without the whole research run around it. It is a normal source like any other, so it shows up in the sources panel and you can unlink it there.

When the assistant asks you something

Instead of guessing, the assistant can ask a question back: a choice from a few options, several at once, or an open question. It appears as a card above the input bar so it cannot scroll out of view, one question at a time with a counter and arrows when there are more. Paging forward keeps your answer, Skip drops it, and Send only becomes available on the last one.

You are never forced: keep typing and the question closes itself, with "You continued without choosing; the assistant decided for itself." Answered questions move into the action timeline of that turn.

Steering an answer

Move over a message and three ways to go on appear:

  • Edit, on your own messages. You change the text and choose Save and send again. Everything from that message on lapses and the conversation runs again from there.
  • Retry with a different model, on an answer. You pick a model from the list and the conversation goes on with that model.
  • Continue from here in a new conversation, also on an answer. A new conversation appears with the history up to and including that message and the same settings; the original stays untouched. Handy for exploring a side path without polluting your main line. How those branches hang together is shown in the Graph on the conversations page.

When a conversation gets long

When a conversation grows towards the context window of your model, Omnissiah summarises the oldest turns for the model. A divider appears in the stream: "Messages above are summarized for the model." Click it and you read the summary it gets instead: "The messages above the divider no longer go to the model word for word; it gets this summary instead. For you the full conversation simply stays."

Nothing changes for you: the full conversation stays visible and stored. You cannot force it or undo it by hand; you can switch it off entirely, with Context compression under Settings → General → Helper tasks.

What a turn cost

The header shows the token usage and an estimate of the cost of this conversation. The little ring next to it shows how much of the context window the last turn actually used. When a turn has tools, the budget per run comes after it.

Click the token line under an answer for Details of this reply: input, output, what came from the cache, how long it took, and under "What went in" which sources went along and which were left out, with the reason.

Stopping, waiting and going on

While it is generating there is a stop button, and Escape does the same. An interrupted answer stays with a note that it is incomplete. If the assistant runs into its step limit or its token budget, it says so and offers Continue.

Send something while an answer is still running and it depends on the setting While generating: Queue makes your message wait until the turn is done, Interrupt cuts the running answer short and steers right away. The queue is one deep; send something else and it replaces the waiting message.

Finding what you already discussed

The menu of a conversation holds Pin, Rename, Labels, Move to project, Export as Markdown or JSON, and Delete. A pinned conversation stays at the top of the sidebar.

You can search in two places. The command bar (⌘K, or Ctrl+K) searches your conversations and runs actions right away; the conversations page has its own search over titles and messages. The assistant can reach them too: the tool Conversation history lets it look up and read back an older conversation.

What you switch on per conversation

Behind the + on the input bar sits a list Skills, and typing / opens the same skills as a menu; either way a skill becomes a chip above the input bar and goes along with the next message only, see Skills. There is no list of tools there any more. What the model can do now follows from three things instead: tools that are always available, the settings of this conversation (a linked folder and whether it may write, the approval level, whether the project is source-bound), and what you have configured - web search exists once there is a Tavily key, and MCP servers you switch on for the whole app under Settings → Tools.
