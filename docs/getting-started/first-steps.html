Getting started

First steps

Omnissiah arrives empty. There is no model inside the app: you connect your own key from a cloud provider, or you run a model on your own machine. As long as there is neither, the app shows "No model available yet" instead of an input bar that cannot do anything.

The interface is in English

Omnissiah starts in English. Would you rather read Dutch? Go to Settings → General → Language and click "Nederlands". It sits right under your name, as two buttons side by side, and each language is written in its own language ("English", "Nederlands"), so you can point at the right one without reading the rest. The whole interface follows immediately, including the desktop app's menu.

Two things do not follow that setting. The language the model answers in follows the language you write in: write Dutch in an English interface and you get a Dutch answer. And jargon stays in the language it works in, so a tool keeps the name it has in every other tool.

Adding a model

Click Settings at the bottom left of the sidebar and go to Models. There are three ways in.

Cloud provider. Under "Add an API (cloud) model", pick Google or Anthropic, paste your API key and click Add. Omnissiah checks the key with the provider right away, so you know immediately whether it works. You only need one; two is fine too, and then you can switch per conversation. Keys stay server-side and never reach the browser.

Local model. If a local server is already running on your machine, Omnissiah usually finds it by itself and you see "Ollama found at …" with a Connect button. If you have nothing yet, click Discover models: that searches the models on Hugging Face and downloads one straight to your local server. Free, private and without a key. There is more about this on Models.

Your own endpoint. Under "Your own endpoint" you connect OpenRouter, Groq or your own gateway: a name, the base URL, and the API format that endpoint speaks. Pick that format by what the endpoint speaks, not by the brand name of the model, because a gateway often serves models from another provider.

Your first conversation

Start a new conversation and type your question. There is no mode to pick first: you simply talk, and the assistant gets more to work with as you give it more.

The model is the one choice in the bottom row of the input bar. The picker shows everything you have access to, cloud and local mixed together. A new conversation starts with the model you used last, so that choice remembers itself.

Everything else follows from settings you can see, in the bar under the input bar:

  • Link a folder with Work in a folder and the assistant can read the files in it. Set that folder to Read and write and it may change them and use a terminal as well. What it may do without asking is the approval level next to it. See Working in a folder.
  • For a longer investigation, open the + and pick Deep research, or type /research. That applies to your next message and ends with a saved report.

So there is nothing to switch on to get started. A plain question in a fresh conversation just works.

How deeply the model thinks

The model picker has an Effort row: how thoroughly the model may think before it answers. More means a better considered answer, but also longer waiting and more tokens. The chosen level is shown next to the model name.

The levels are called Off, Low, Medium, High, Extra high and Max, and which ones exist differs per model: Omnissiah only offers what that model actually knows, with a line explaining anything that is missing. Switch to a model that does not support your level and you will see it fall back.

What you can turn on later

None of this is required, but it is there if you want it:

  • Web search in Settings, so the assistant can look up current information. That needs a key of its own.
  • Sources per conversation or per project. The Sources button at the top right (the one with the counter) opens the list; there you add text, a file or a URL, or link a folder. Everything the model can see in this conversation is in that one list. Drag a file onto the input bar and it goes along as an attachment with that message, and appears in the same list. See Sources.
  • Memory, so the assistant remembers things about you and your work between conversations. See Memory.
  • Personas and skills to fix its role and its way of working. See Personas and Skills.
  • MCP servers to attach tools that Omnissiah does not have itself. See MCP servers.
