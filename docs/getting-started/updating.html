Getting started

Updating

The desktop app checks for a new version shortly after starting, and you can force a check yourself through the menu → Check for updates….

Nothing happens quietly. If there is a new version, an item appears at the bottom of the sidebar naming that version. Nothing is downloaded until you click; the item simply stays there until you pick it up.

Windows

The item says "Ready to download." with a Download button. While it downloads you see the progress in percentages, and when it is finished it says the version is ready and asks you to restart. The Restart button then installs the new version and starts the app again, so you decide the moment yourself and are never interrupted halfway through something.

If a download fails, the item says so and offers Retry.

Coming from 0.23.2 or older

Version 0.24.0 renames the app from Omnissiah to Babbage. Windows treats the new version as a different application: the Babbage installer does not remove Omnissiah, and the in-app updater of your current Omnissiah will still offer 0.24.0 and, if you let it, install Babbage next to it and start it straight away, before you have moved your data. Do not take that route. Decline the update and do the one-time manual switch below. Every update after that works as described above.

Move your data first, then install. The app data folder is named after the app, so a fresh Babbage looks in %APPDATA%\Babbage and starts empty while everything you had sits next to it in %APPDATA%\Omnissiah. Nothing is lost and nothing warns you either. Babbage creates that folder, a fresh session secret and an empty database the very first time it starts, so do this before that first start:

  1. Rename the folder %APPDATA%\Omnissiah to %APPDATA%\Babbage.
  2. Inside it, in data\, rename omnissiah.db to babbage.db. If omnissiah.db-wal and omnissiah.db-shm are there, rename those to babbage.db-wal and babbage.db-shm as well.
  3. Open .env in that folder and rename every key that starts with OMNISSIAH_ so that it starts with BABBAGE_, keeping the values: OMNISSIAH_AUTH_SECRET becomes BABBAGE_AUTH_SECRET, and each OMNISSIAH_CUSTOM_KEY_… (the key of a custom endpoint) becomes BABBAGE_CUSTOM_KEY_…. Your provider keys (Google, Anthropic, Tavily) do not carry the name and stay as they are. Skipping the session secret only logs you out once; skipping a custom-endpoint key leaves that endpoint without a key until you rename the line.

Then uninstall Omnissiah through Settings → Apps and install Babbage 0.24.0 from the download page. On the last page of the installer, untick Run Babbage if you still have steps to do. The installer leaves the old program folder %LOCALAPPDATA%\Programs\Omnissiah alone; delete it by hand once Babbage runs.

If Babbage already started before you moved your data, close it, delete the fresh %APPDATA%\Babbage it created, and then do the three steps above.

Snapshots. The folder snapshots the app makes before a shell command changes anything stay on disk, but Babbage looks for them under a new name. For a linked folder you can carry them over by renaming omnissiah to babbage in %APPDATA%\Babbage\data\snapshots\store\refs\, as long as that folder still contains files; if it is empty, git has packed the snapshots and the rename does nothing. Snapshots of a conversation's own workspace cannot be carried over at all, because their name is derived from the data folder's path, which just changed. They are a safety net of at most thirty days, so losing them is acceptable.

Uninstalling 0.21.0 through 0.23.1. The uninstaller that shipped with those versions fails its own integrity check ("Installer integrity check has failed") before it touches a single file. If Settings → Apps stops on that message, delete Uninstall Omnissiah.exe in %LOCALAPPDATA%\Programs\Omnissiah (paste that path into the address bar of Explorer), then delete that whole folder. Your data lives in %APPDATA%, not there, and stays untouched.

macOS

On the Mac the item says "Download it and install it over this one." and the button is Download page. There you fetch the new .dmg and install it over the old one, just like the first time. That is not an oversight: an app that is not signed is not allowed to replace itself on macOS.

Your data stays. It lives in the app data folder and not in the app itself, so reinstalling does not touch your conversations and settings. See Data and backup.

Coming from 0.23.2 or older

Version 0.24.0 renames the app from Omnissiah to Babbage, and that is the one update where the sentence above does not hold on its own. A fresh Babbage looks in ~/Library/Application Support/Babbage and starts empty while everything you had sits next to it in ~/Library/Application Support/Omnissiah, with no warning either way. Babbage creates that folder, a fresh session secret and an empty database the very first time it starts, so move your data before that first start:

  1. Rename the folder ~/Library/Application Support/Omnissiah to ~/Library/Application Support/Babbage.
  2. Inside it, in data/, rename omnissiah.db to babbage.db, and do the same for omnissiah.db-wal and omnissiah.db-shm if they are there.
  3. Open .env in that folder and rename every key that starts with OMNISSIAH_ so that it starts with BABBAGE_, keeping the values: OMNISSIAH_AUTH_SECRET becomes BABBAGE_AUTH_SECRET, and each OMNISSIAH_CUSTOM_KEY_… (the key of a custom endpoint) becomes BABBAGE_CUSTOM_KEY_…. Your provider keys (Google, Anthropic, Tavily) do not carry the name and stay as they are. Skipping the session secret only logs you out once; skipping a custom-endpoint key leaves that endpoint without a key until you rename the line.

Then drag Omnissiah.app to the trash and install Babbage 0.24.0 from the download page as usual. If Babbage already started before you moved your data, quit it, delete the fresh ~/Library/Application Support/Babbage it created, and then do the three steps above.

Snapshots follow the same rule as on Windows: for linked folders, rename omnissiah to babbage in data/snapshots/store/refs/ while that folder still contains files; workspace snapshots cannot be carried over, and all of them are a safety net of at most thirty days.
