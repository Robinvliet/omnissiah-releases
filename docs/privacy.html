Privacy and security

Omnissiah is built to run on one machine, belonging to one person. That is not a detail but the starting point: there is no server owned by someone else sitting between you and the model.

The server only listens on your own machine

The built-in server binds to 127.0.0.1 only, the address that only that machine can reach. Not your wifi network, not the internet. That holds for the desktop app and for the web version (APP_BIND).

That is why the desktop app has no password: only someone logged in on your machine can reach it, and they could already reach the data files anyway. A password would add nothing there.

The web version does keep a password, because it can be reached by several devices through Tailscale. tailscale serve stays inside your own tailnet, so inside your own logged-in devices.

Your keys stay server-side

API keys live in .env and are only read server-side. They never reach the browser, appear nowhere in the HTML and are not in the network requests you would see in the developer tools.

MCP servers do not get them either: a local stdio server starts with a clean environment, plus only the variables you specify for it yourself.

There is no telemetry

Omnissiah sends no usage statistics, no crash reports and no anonymous data. There is no account and no login with a service run by the maker.

What does leave your machine

Only what you set in motion:

  • To your model provider goes the content of the conversation, including the sources that come along for that turn: your documents or fragments of them, the files you attached, and what the assistant has read from a linked folder. That is inherent to a cloud model, and it applies just as much to an endpoint you connected yourself. If you would rather not, use a local model: then nothing leaves your machine.
  • To the search engine goes your query, if you have web search turned on.
  • To a web page goes a request, when the assistant fetches a page for you.
  • To Hugging Face goes a request when you use "Discover models".
  • To GitHub goes a request when the desktop app checks for updates, and when you fetch a skill from a repository.
  • To api.osv.dev goes the name and version of a package before a local MCP server is started with npx or uvx. That is a check against a public database of known malware, and only that: it fails open, so a failed check does not block the server.

The local embedding model that makes your documents searchable runs on your own machine. No document text goes out to be indexed.

What comes in is looked at first

Text from outside can contain instructions that are not yours but do talk to the model. Omnissiah therefore scans everything that enters your conversation from outside for such patterns before the model sees it: documents you add, pages the assistant fetches, search results, what an MCP server sends back, and the files you attach.

If the scan finds something, you see a flag on that source and the model is told explicitly: this is material to read, not an instruction to carry out. A flagged document stays out of the block that goes along in full, but the assistant can still read it when it needs it; a flagged attachment is inside your message and cannot be left out of it, so it is named. You can have a flag reassessed with Reassess, without adding the source again.

Be honest here too about what this is: it recognises patterns, it does not understand intent. It is there to warn you and to arm the model, not to protect you from material you bring in yourself.

What you control yourself

Agent mode can read and write files and run commands, but only inside a folder you link explicitly, and only at the level you set with the approval level. There are safety nets underneath, such as checkpoints before a write and snapshots before a shell command.

Be honest about what that is and is not: those layers prevent accidents, they are not a security boundary. The real boundary is your operating system. So do not link a folder whose contents you would not want to lose without a backup, and do not add an MCP server you do not trust. See MCP servers.

Your data is yours

Everything lives in one data folder, in a database you can open with any SQLite tool, plus ordinary markdown files. No proprietary format, no export step, no service that has to give permission first. See Data and backup.

What the assistant remembers about you between conversations lives there too, and you can read it back, edit it, wipe it or turn it off entirely. See Memory.
