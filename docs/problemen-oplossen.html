Problemen oplossen

De app start niet

De foutmelding toont de bundel- en datamap. Herinstalleren van de nieuwste versie via de downloadpagina is meestal de snelste oplossing; je data blijft daarbij staan, want die woont in de appdata-map en niet in de app zelf.

macOS zegt dat de app beschadigd is

Dat hoort erbij en hij is niet beschadigd: de app is bewust niet ondertekend, en macOS blokkeert hem daarom de eerste keer. Eenmalig per versie op te heffen via Systeeminstellingen → Privacy en beveiliging → Toch openen, of in Terminal met xattr -cr /Applications/Omnissiah.app. Zie Installeren.

Windows waarschuwt bij de installer

SmartScreen toont "Windows heeft je pc beschermd" → Meer informatie → Toch uitvoeren. Eenmalig per versie, en dezelfde reden: de installer is niet ondertekend.

Er staat geen enkel model in de kiezer

Dan is er nog geen sleutel en geen lokale server. Ga naar Instellingen → Modellen; Eerste stappen loopt dat na.

De provider geeft een foutmelding

Omnissiah toont de melding met de naam van de provider erbij. Een paar komen vaak voor:

  • 429 bij Gemini: de gratis tier heeft krappe limieten op de pro-modellen. Wacht even, of kies een flash-model.
  • 503 bij Gemini: flash is tijdelijk overbelast.
  • 529 bij Anthropic: overbelast.

De praktische oplossing is telkens dezelfde: wissel van model of van provider en probeer het opnieuw. Het gesprek blijft gewoon staan, en een ander model kan verder waar het vorige gebleven was.

Een lokaal model blijft zoeken en geeft geen antwoord

Kleinere modellen kunnen bij tools in een lus belanden en hun beurt beëindigen zonder eindantwoord. De stappenlimiet kapt dat af. Kies een groter model, vanaf ongeveer 8B, of zet de tools uit voor dat gesprek. Zie Modellen.

"De prompt past niet in het contextvenster van de lokale server"

Dit is bijna altijd agent-modus op een Ollama met het standaard contextvenster van 4096 tokens. De beschrijvingen van de tools tellen mee in de prompt, en met een gekoppelde map erbij past het niet meer. De melding toont er de tekst van je server letterlijk bij, inclusief hoeveel tokens er gevraagd werden.

Twee oplossingen. Verhoog het venster van je server (in de Ollama-app onder Context length, of start hem met OLLAMA_CONTEXT_LENGTH=16384) en start hem opnieuw. Of maak de prompt kleiner: koppel de map of bronnen los, of begin een nieuw gesprek. Zie Modellen.

Het antwoord stopt halverwege

Staat er "Antwoord afgekapt: de uitvoerlimiet van dit model is bereikt", dan wilde het model meer schrijven dan er ruimte was. Bij een lokaal model hangt die ruimte aan het contextvenster van je server, dus een groter venster geeft ook langere antwoorden. Je kunt ook gewoon vragen om verder te gaan.

Vers beginnen

Sluit de app en verwijder de datamap. Dat wist al je gesprekken en instellingen. Zie Data en backup.

Webversie: poort 3000 is al bezet

Zet APP_PORT=3001, of een andere vrije poort, in .env en start opnieuw met docker compose up -d.

Webversie: wat doet de app eigenlijk

docker compose logs -f

Webversie: wachtwoord kwijt

Verwijder de regel authPasswordHash uit de settings-tabel in data/omnissiah.db met een SQLite-tool. Het loginscherm toont dan weer "stel een wachtwoord in", en je gesprekken blijven staan.

Webversie: iets klopt niet na een update

docker compose build --no-cache

Dat forceert een schone herbouw.

Webversie: native module-fout (better-sqlite3)

Bouw via docker compose up -d --build. De module wordt dan ín de container voor Linux gecompileerd, in plaats van vanaf je host gekopieerd.
