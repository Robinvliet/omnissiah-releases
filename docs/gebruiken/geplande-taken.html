Werken met Omnissiah

Geplande taken

Een geplande taak is een opdracht die vanzelf draait: elke ochtend, elke werkdag, één keer volgende week. Je vindt ze via Geplande taken in de zijbalk.

Een taak bestaat uit drie dingen: een naam, een schema, en de opdracht die elke run uitvoert. Die opdracht draait in een eigen taakgesprek, altijd in agent-modus. De dialoog zegt waarom dat uitmaakt: "Een geplande taak draait automatisch in een eigen taakgesprek in Agent-modus. Schrijf de opdracht zelfstandig: de taak kent geen andere gesprekken."

Een taak maken

Klik op Nieuwe taak en vul in:

  • Naam. Kort, hij staat in de lijst en wordt de titel van het taakgesprek.
  • Opdracht. "Elke run begint met deze opdracht als bericht in het taakgesprek." Schrijf hem dus zo dat hij op zichzelf leesbaar is, alsof je hem aan iemand geeft die verder niets weet.
  • Schema. Een keuzelijst met Dagelijks, Werkdagen, Wekelijks, Elk uur, Eenmalig, Elke X minuten en Cron-expressie, met daarnaast het veld dat erbij hoort: een tijdstip, een weekdag, een datum, een aantal minuten of de expressie zelf. Eronder staat meteen wat je gekozen hebt: "Volgende run: 7 aug 09:00", of de reden waarom het schema nog niet klopt.
  • Model en Goedkeuring. Beide gelden voor het taakgesprek. Het goedkeuringsniveau werkt precies zoals in een gewoon agent-gesprek; zie Agent-modus.

Tijden worden gelezen in de tijdzone van de machine waar Omnissiah draait, en dat is jouw eigen machine.

Of vraag het gewoon in een gesprek

Je kunt de assistent ook vragen iets in te plannen. Hij vertaalt je zin zelf naar een schema en doet een voorstel dat pauzeert tot jij het goedkeurt, net als bij een skill. De taak erft dan het model, het goedkeuringsniveau en het project van het gesprek waarin je het vroeg; bijstellen kan daarna in het overzicht.

Deze tool heet Taken plannen in de lijst onder Toevoegen op de invoerbalk, en je kunt hem daar per gesprek uitzetten.

Wat je terugziet

Draait er een run af, dan verschijnt er een teller bij Geplande taken in de zijbalk en een melding: "Geplande taak 'Ochtendbriefing': run gelukt", met een knop Bekijken. De teller dooft zodra je de takenpagina bezoekt.

Op de pagina van één taak staan het schema, de volgende run, de laatste status en de opdracht zelf, met daaronder de lijst Runs. Bovenin staan Taakgesprek (spring naar het gesprek), Nu draaien ("Run gestart - de uitkomst verschijnt in het taakgesprek"), en in het menu Bewerken, Pauzeren of Hervatten, en Verwijderen.

Elke run heeft een status:

  • gelukt - de run is afgerond.
  • mislukt - er ging iets mis; de reden staat erbij.
  • stil - de run is gedraaid en had niets te melden. Zie hieronder.
  • wacht op goedkeuring - de assistent wil iets doen waar jij eerst ja op moet zeggen. Dat doe je in het taakgesprek.
  • overgeslagen - deze run is niet gedraaid, met de reden erbij.
  • bezig - hij loopt nu.

In het taakgesprek

Alle runs van een taak staan achter elkaar in hetzelfde gesprek, en dat wordt lang. Daarom toont de chat standaard alleen de laatste run, met bovenin een pager: Run 3 van 12, met het tijdstip erachter, pijltjes naar vorige en volgende, en Alles tonen als je toch de hele geschiedenis wilt zien. Klik je in de runlijst op een run, dan opent het gesprek meteen op die run.

Wanneer een run niets zegt

Een taak die elke ochtend het nieuws samenvat heeft niet elke ochtend nieuws. In zo'n geval antwoordt de assistent met [SILENT], en dan krijgt de run de status stil en blijft de melding weg. De beurt staat gewoon in het taakgesprek, dus je kunt altijd nakijken dát hij gedraaid heeft.

Dat is ook wat de taak in zijn instructies meekrijgt: hij draait zonder aanwezige gebruiker, stelt geen vragen en wacht nergens op, want zijn laatste antwoord is wat jij later als uitkomst ziet.

Als de app uit stond

Een geplande taak heeft een draaiende app nodig. Stond je computer uit om negen uur, dan draait de ochtendbriefing alsnog zodra je Omnissiah weer opent.

Opgestapelde gemiste runs vervallen wel: er wordt er één ingehaald, niet vijf. Dat is zichtbaar als een overgeslagen run met de reden erbij: "Geplande run van 6 aug 09:00 gemist (server stond uit); één inhaal-run gedraaid, eerdere gemiste runs vervallen." Een eenmalige taak die nog niet gedraaid heeft, draait hoe laat het ook is.

Wanneer een run wordt overgeslagen

Twee situaties, en allebei zie je ze in de runlijst staan in plaats van dat ze stil gebeuren:

  • "Het taakgesprek is op dit moment in gebruik; deze run is overgeslagen." Je bent zelf in dat gesprek aan het werk.
  • "De vorige run wacht nog op een goedkeuring in het taakgesprek." Zolang die openstaat kan er geen nieuwe beurt overheen. Keur hem goed of wijs hem af, en het schema loopt vanzelf weer.

In beide gevallen schuift de taak door naar zijn volgende moment.

Als er iets misgaat

Een mislukte run valt niet stil weg. In het taakgesprek verschijnt een bericht dat begint met "De geplande run kon niet worden afgerond:", met de melding erachter, en in de runlijst staat dezelfde reden.

Gaat het drie keer op rij mis, dan pauzeert de taak zichzelf en staat dat erbij: "De taak is gepauzeerd na 3 mislukte runs op rij." Een kapotte taak hoort niet weken door te draaien. Los je de oorzaak op, dan zet je hem weer aan met Hervatten.

Waar geplande taken niet bestaan

In een project met Antwoord alleen uit de bronnen kun je geen taken aanmaken en draaien bestaande taken niet: ze werken in agent-modus, en die bestaat daar niet. Zie Projecten. Stond de taak er al voordat je die schakelaar aanzette, dan pauzeert hij zichzelf in plaats van elke keer opnieuw te falen.

Een geplande run maakt zelf ook nooit nieuwe geplande taken aan. Dat is niet aan de goede wil van het model overgelaten: de tool zit er tijdens een run domweg niet in.

Verwijderen tenslotte haalt de taak weg, niet je werk: "Het taakgesprek met de eerdere runs blijft gewoon bestaan."
