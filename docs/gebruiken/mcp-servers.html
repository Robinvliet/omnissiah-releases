Werken met Omnissiah

MCP-servers

Via Instellingen → Tools koppel je MCP-servers die het model extra tools geven, bijvoorbeeld toegang tot een bestandssysteem, git of een externe dienst. Per gesprek zet je daarna aan welke tools mee mogen.

Er zijn twee smaken.

Extern (HTTP of SSE)

Een URL, optioneel met een Authorization-header. De server draait ergens anders; Omnissiah praat er alleen mee.

Lokaal (stdio)

Een commando dat Omnissiah aan het begin van een beurt als proces start en daarna weer afsluit. Dit is het gangbaarste type voor persoonlijk gebruik: de officiële servers voor onder andere bestanden en git zijn stdio.

Voorbeeld: commando npx, argumenten -y @modelcontextprotocol/server-filesystem /pad/naar/map. Omgevingsvariabelen, bijvoorbeeld een GITHUB_PERSONAL_ACCESS_TOKEN, vul je in als regels NAAM=waarde; die waarden blijven server-side en zijn in de app nergens terug te lezen.

Wat je moet weten voordat je er een toevoegt

Het commando draait op de machine waar Omnissiah draait, met de rechten van je eigen account. Een stdio-server registreren ís een lokaal commando configureren. Voeg alleen servers toe die je vertrouwt.

Als vangnet controleert Omnissiah npx- en uvx-packages vóór het starten tegen de OSV-database op bekende malware. Alleen bevestigde malware blokkeert, en de check is fail-open bij netwerkproblemen: hij is een extra paar ogen, geen slot.

Kale commando's worden gevonden. npx en vergelijkbaar werken ook als de desktop-app met een minimale PATH gestart is; Omnissiah kijkt ook in de Homebrew-, /usr/local/bin- en ~/.local/bin-locaties. Werkt het toch niet, gebruik dan een absoluut pad naar het commando.

In de Docker-webversie draait het commando ín de container. npx is daar aanwezig, want de container draait op een Node-image; uvx en Python-servers niet.

Het kindproces krijgt een schone omgeving. Alleen PATH, HOME en vergelijkbare basisvariabelen plus wat jij zelf opgeeft. Je API-sleutels uit .env lekken er niet naartoe.

Toevoegen is meteen een test

De knop heet niet voor niets Toevoegen (test verbinding). Omnissiah maakt eerst verbinding en haalt de toollijst op; lukt dat niet, dan krijg je de reden te zien en wordt er niets opgeslagen. Je hebt dus nooit een server in je lijst waarvan pas midden in een gesprek blijkt dat hij niet werkt.

In de lijst staat per server wat je hebt ingevuld: de URL of het commando met zijn argumenten, en of er een auth-header of omgevingsvariabelen bij horen. De waarden zelf staan er niet; die zijn na het opslaan niet meer terug te lezen.

Per gesprek aanzetten

Een gekoppelde server doet nog niets uit zichzelf. Klik in een gesprek op Toevoegen op de invoerbalk en open de lijst Tools: daar staan de ingebouwde tools en onder elke MCP-server zijn eigen tools, stuk voor stuk aan of uit te zetten. Onderaan staat waar die keuze geldt: "Geldt alleen voor dit gesprek. MCP-servers beheer je via Instellingen."

Standaard staat alles aan. Uitzetten is nuttig als een server veel tools meebrengt: elke beschikbare tool kost ruimte in de prompt, en een kleiner model raakt eerder de weg kwijt in een lange lijst.

Wat je in een gesprek ziet

Roept de assistent een tool van een server aan, dan verschijnt die stap in de actie-tijdlijn met de naam van de tool en een klein label met de servernaam ernaast, zodat je ziet waar hij vandaan komt. Achter de schermen dragen ze een langere naam, mcp__<server>__<tool>, zodat twee servers met een tool die hetzelfde heet elkaar niet in de weg zitten.

Een aanroep die na vijf minuten nog geen antwoord heeft gegeven wordt afgebroken, met de melding dat de server binnen die tijd niets terugstuurde. Zonder die grens zou één trage server je hele beurt laten hangen.

Goedkeuring

In agent-modus vallen tools van MCP-servers onder het goedkeuringsniveau van dat gesprek, net als bestanden schrijven en de terminal. Zie Agent-modus.

Eén verschil is de moeite waard: in de stand Automatisch goedkeuren gaat een MCP-tool alleen zonder vragen door als de server hem zélf als alleen-lezen aanmerkt. Al het andere pauzeert. Dat is expres voorzichtig, want die aanmerking komt van de server en die heb je niet zelf geschreven.

In chat- en research-modus is er geen goedkeuringsstap: daar draaien MCP-tools zonder te vragen. Dat is nog een reden om alleen servers toe te voegen die je vertrouwt.

Als een server het niet doet

Een server die aan het begin van een beurt niet wil verbinden wordt overgeslagen. De beurt gaat gewoon door, met de tools van de servers die het wél doen, en je ziet het in de chat: boven het antwoord staat "1 MCP-server niet beschikbaar", en als je dat blok openklapt de naam van de server met de reden erachter. Die melding hoort bij dát antwoord en blijft er dus ook na een herlaad bij staan.

De assistent krijgt precies dezelfde melding in zijn instructies. Hij kan daardoor zeggen dat hij ergens niet bij kon, in plaats van zelfverzekerd te antwoorden uit een onvolledig beeld. Eén kapotte server houdt de beurt nooit tegen; hij wordt alleen niet meer verzwegen.

De reden is de foutmelding van de server zelf, ingekort en met eventuele sleutels eruit gefilterd. Zegt die te weinig, dan staat de volledige fout in de serverlogboeken. Wat de assistent van andere servers wél kreeg blijft daar los van staan.
