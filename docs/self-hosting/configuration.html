Self-hosting

Configuration

All settings for the web version live in .env, copied from .env.example. Most of them you never need to touch.

The desktop app manages its own .env in the app data folder and handles this through Settings; this page is about self-hosting.

The variables

Variable Default What it does
APP_BIND 127.0.0.1 (Docker) Which host address the port is published on. Localhost only by default.
APP_PORT 3000 (Docker) The port on your computer. Set it to 3001, for example, if 3000 is taken.
OMNISSIAH_AUTH_SECRET empty Secret for signing your login session. Leave it empty: Omnissiah generates one and stores it here.
GOOGLE_GENERATIVE_AI_API_KEY empty Google Gemini key.
ANTHROPIC_API_KEY empty Anthropic Claude key.
TAVILY_API_KEY empty Tavily key for web search.
LOCAL_AI_BASE_URL empty Base URL of a local, OpenAI-compatible server. See Models.
LOCAL_AI_API_KEY empty Optional token for that local server. Only needed with authentication; Ollama does not have it.
WORKING_DIR_ROOT your home folder The folder within which you can link a local folder to a conversation. See below.
OMNISSIAH_DATA_DIR the project dir Base folder for data/, skills/ and .env. Leave it empty, in Docker too.

Setting API keys

There are two ways. Pick one.

In the app, which is the easiest: go to Settings → Models and paste your keys there. Omnissiah checks them live and writes them to .env. This works immediately, without a restart.

Up front in .env: fill in the values before starting. If you edit .env by hand later, restart the app, in Docker with docker compose up -d, so the new values are read.

Keys are read server-side only and never reach the browser.

Which folder the assistant may see

With "Add folder" in the plus menu of the input bar you link a folder to a conversation. The assistant can then read the files in that folder, and edit them too when you set that folder to read and write.

How you point at that folder differs per way of running:

  • Desktop app: your system's normal folder picker, Finder or Explorer. Whatever you point at is allowed, including an external drive.
  • Web version: a browser cannot open such a picker, so you browse in a dialog of our own starting at WORKING_DIR_ROOT, your home folder by default. Anything outside it is not reachable. Set a specific path to narrow it down, or * for no limit.
  • Docker: the container only sees your host folders if you mount them. Add a volume in docker-compose.yml, for example - /Users/you/projects:/work, and set WORKING_DIR_ROOT=/work in .env.

What the model may touch does not change here: the file tools always work inside the chosen working folder itself, not inside the root. WORKING_DIR_ROOT only decides what you can pick.
